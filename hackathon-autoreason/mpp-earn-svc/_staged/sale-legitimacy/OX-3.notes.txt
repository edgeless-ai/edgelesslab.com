Design decisions worth flagging to the human reviewer:
1. Disqualifier order is a strict if/elif chain (not_live_paid → at_cost → self_purchase/arms_length → no_creator) exactly in the packet's listed order, so each disqualifier's test gets a single, unambiguous reason string. This matches every acceptance-criteria example given.
2. `arms_length` is checked BEFORE the `royalty_reason == 'self_purchase_no_royalty'` fallback, since arms_length is described as the authoritative server-side signal; the royalty-reason check exists as a defense-in-depth backstop in case a caller passes arms_length=(True, ...) despite main.py's legacy free-text self-purchase branch having fired.
3. `payer` is a NEW dict shape (`{"payer_key", "charge_id"}`) that doesn't exist anywhere in the current codebase yet — resolving `payer_key` server-side from the Stripe charge (card fingerprint / customer id) is explicitly OUT OF SCOPE for this packet per Fable's framing ("buyer identity is derived SERVER-SIDE from the Stripe charge... NEVER body['buyer']") and is presumably a companion packet. `qualify_sale` takes it as an already-resolved input.
4. `prior_records` schema (`payer_key`, `design_key`, `charge_id`, `ts`) is inferred from the packet's description of what the diminishing/velocity logic needs; the future caller that wires this into main.py's webhook handler is responsible for persisting exactly this shape via `state_store.put_record()` for every qualifying sale, and for loading the relevant slice (e.g. via `state_store.list_records('oxygen')`) before calling `qualify_sale`.
5. Neither oxygen.py nor test_oxygen.py were written into the actual repo — both only exist in the scratch directory used to verify the tests pass.
