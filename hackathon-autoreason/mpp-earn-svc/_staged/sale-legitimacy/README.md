Design decisions encoded: buyer identity = Stripe Charge `payment_method_details.card.fingerprint` + `billing_details.email` / `session.customer_details.email` (server-side, never body['buyer']); unresolved payer fails CLOSED for oxygen but fails OPEN for royalty (never stop paying a legit creator because a wallet PM lacked a card fingerprint); pending-royalty sales (creator_not_onboarded / onboarding_incomplete) still count as oxygen (they are arms-length margin sales — the royalty is owed, just parked); at-cost and self-purchase sales are never oxygen and no longer move the limited-edition cap.

### OX-1 — Server-side payer identity resolver (oxygen.py — new module)
- **file:** /Users/djm/claude-projects/hackathon-autoreason/mpp-earn-svc/oxygen.py
- **goal:** Derive buyer identity from the Stripe charge itself — card fingerprint, payer email, customer id — so no downstream check ever reads the forgeable body/metadata 'buyer' string (main.py:863, sourced from client body at main.py:2673).
- **approach:** NEW file oxygen.py (nothing imports it yet — safe to create for real). Implement `resolve_payer(session: dict, charge_id: str | None) -> dict` (synchronous; callers run it via asyncio.to_thread like every other Stripe call in main.py, e.g. :886). Steps: (1) if charge_id, `ch = stripe.Charge.retrieve(charge_id)` — pull `fingerprint = (ch.get('payment_method_details') or {}).get('card', {}).get('fingerprint')` (this is Stripe's stable per-card-number id; also check `payment_method_details.card_present.fingerprint` fallback and tolerate non-card PMs → None), `payer_email = (ch.get('billing_details') or {}).get('email')`, `customer = ch.get('customer')`, `livemode = ch.get('livemode')`. (2) Merge session-side identity the way main.py already reads it (main.py:639/662): `session.get('customer')` and `(session.get('customer_details') or {}).get('email')` as email fallback (Checkout always collects it). (3) Return `{'fingerprint', 'email' (lowercased/stripped), 'customer_id', 'charge_id', 'livemode', 'resolved': bool}` where resolved = bool(fingerprint or email). (4) Add `payer_key(payer) -> str`: `'fp:'+fingerprint` if present else `'em:'+sha256(email)[:16]` else `''` — the canonical de-dup key; store only the SHA-256 of the email, never raw PII, in oxygen records. (5) Wrap the Stripe call in try/except returning `{'resolved': False, 'error': str(e)[:120]}` — resolver must NEVER raise into the webhook. Match module conventions: stdlib only + the already-imported `stripe`, mirror the defensive dict-access style of _recipient_from_session (main.py:656-674). Include `tests/test_oxygen_identity.py` using plain dict stubs and monkeypatched `stripe.Charge.retrieve` (no network).
- **acceptance:** python -m pytest tests/test_oxygen_identity.py passes with cases: (a) card charge → fingerprint + resolved=True; (b) wallet/no-card PM but session customer_details.email present → resolved=True with em: key; (c) no charge_id + no email → resolved=False; (d) Charge.retrieve raising → resolved=False, no exception; (e) payer_key stable and email hashed (assert raw email not in json.dumps of any record-shaped output). grep confirms oxygen.py never references body['buyer'] or meta['buyer'].

Getting resolved-semantics wrong here poisons every downstream check.
